# 教学楼巡逻原型

## 系统方案

手机连接车载 ESP-01S 热点。Android 保存用户指定的途经点、绘制占据栅格，并在已扫描的空闲区域规划路径。TM4C 在本地驱动双轮、连续扫描、判断障碍。手机退出控制页或 Wi-Fi 中断后，车端按通信超时逻辑将左右轮指令置零。ESP 使用 AT 固件，无需重新烧写模块。

首次巡逻从地上标记的起点出发，探头朝车头，地图上方为初始车头方向。固定地图分辨率 20 cm，用于教室和走廊的初步勘察。先验证架空轮向和桌面测距，再测试低速直行、障碍停车和短路线，最后验证自主探索。现阶段位姿由轮速指令积分估算，打滑、堵转和电池电压变化都会积累误差。保存的图可离线查看。要在不同日期可靠复用楼层图，需要轮编码器、起点定位与实地复测。

## 首次运行

1. 打开[逐针接线指南](WIRING.md)，核对电机、Echo 接线、外部 3.3 V 和共地。若 Echo 直连 PB2，先插开发板 DEBUG USB，再开传感器 5 V。关机时先关传感器 5 V，再拔 USB。Wi-Fi 联测和整车落地验收仍待完成。
2. 下载 [TM4C 固件](dist/patrol.bin) 与 [Android APK](dist/patrol-debug.apk)。固件为 TM4C123GH6PM 裸二进制，在 TI UniFlash 选 EK-TM4C123GXL 的 ICDI 调试连接，将二进制加载到 Flash 地址 **0x00000000**，验证写入后复位。也可以用 CCS 加载本地编译的 `build/patrol.elf`。先备份要保留的旧固件，下载时断开电机电源。
3. Android 7.0 及以上安装 APK。手机系统 Wi-Fi 设置中连接 **Patrol-Car**，演示密码 **SurveyCar01**，选择保持此无互联网连接。打开 App →「连接」→ 默认地址 `192.168.4.1` →「新测区」。车端在复位后配置 ESP-01S 为软 AP。默认实验口令随代码公开，多车部署时在 `firmware/radio.c` 中替换口令并重新构建。
4. 修复停车输出并复核四路电平后，架空车轮，按住「前进」验证轮向，松手检查两轮是否停下。地图支持拖动和双指缩放。依次点击添加途经点后，「走路线」允许在未知区域受保护地试探前进，「图上导航」只沿已测为空闲的格子规划。两种模式均避让已知障碍。「自主探索」自动选择已知可达且邻接未知区域的目标，找不到路径时尝试原地扫描。遇到持续缺失的回波、没有进展或找不到出路时任务会暂停。
5. App 自动保存最近测区的栅格，关闭后仍可离线查看。下次「复用原图」前需要把车放回同一个地面标记、朝同一方向。「新测区」收到第一帧有效遥测后开始新地图。手机控制页需保持前台，切后台会断开控制，失联期间车端独立将轮速指令置零。

## 扫描、避障与参照物定位

- TM4C 使用四路 20 kHz PWM 控制 L298N。独立宽定时器在 PC7 输出 50 Hz。舵机按中、左、中、右循环，分别使用 1500、1900、1500、1100 µs。每次转位等待 140 ms 再触发 HC-SR04，GPIO 双边沿中断记录 Echo，30 ms 超时。正前方每约 0.28–0.34 秒重测，两侧每约 0.56–0.68 秒重测。协议同时传回采样时的位姿，可在低速移动中扫描。
- 前方小于 40 cm 时车端将前进指令对应的轮速置零，手机重新规划。侧方较近时车端降低一侧占空比以轻微偏转。原地转向也受前方、侧面净空约束。测距失效、样本过旧或转向后朝向差太大时收回驱动。停车距离还受安装位置、实车速度与轮胎滑行影响。
- 手机用 **201 × 201 格、每格 20 cm** 的局部占据地图。测距射线穿过处累积空闲证据，终点累积障碍证据；规划时将障碍向周围扩大一格，使用四邻接最短路径。空间能覆盖约 40 × 40 m，长条楼层仍可能越界。
- 手机先按车端的时间积分位姿预测。收到一组新的三向测距，且行进约 18 cm 或转向约 18° 后，将回波终点和已有地图中连续、反复观测到的墙段匹配。单墙只调整墙面法线方向的位移，两个独立方向的墙段可修正平面位移。每次最多平移 10 cm，随后才写入该批回波。界面显示最近的“轮速推算 / 超声墙面校正 / 超声双向校正”。当前航向仍靠轮速估算，未实现闭环重定位；相似走廊和移动家具可能造成错误关联。
- 首次实车标定：在已知距离和角度测左右声束的实际方位，填写 `firmware/control.c` 的 `bearing`。量轮距，测固定占空比的实际行驶距离与时间，修正 `TRACK_MM` 与 `FULL_SPEED_MM_S`。测出最大滑行停车距离后再设置净空阈值。仿真中的速度、车宽和车身圆形轮廓都是假设值。测量以车身中心近似声束原点，探头安装偏移会影响近场地图。

## 没有开发板时

在本目录运行。C 编译器、Python 3 和 JDK 可运行测试；Android 构建另外需要 SDK Platform 35 和 Build Tools 35.0.0。车端使用 Arm GNU Toolchain（含 newlib-nano）及 TI TivaWare 2.2.0.295。

```sh
make test
make TIVAWARE=/path/to/TivaWare_C_Series-2.2.0.295
./android/build.sh
make sim
python3 tests/simulator.py --bind 0.0.0.0
```

手机与电脑连同一个 Wi-Fi，把连接地址改为电脑局域网 IP（TCP 7070）。Android 模拟器填写 `10.0.2.2`。仅在电脑本机试验时，模拟器服务默认监听 `127.0.0.1`。应用和真车、模拟车共用[指令 API](API.md)。

## 离线验证与现场验收

| 已执行的离线验证 | 观察结果 |
|---|---|
| 车端交叉编译、APK 构建签名、Android 模拟器连接 PC 模拟车 | 固件可链接，APK 可安装，能读取三向遥测、点选目标并收到路线完成状态 |
| 0.8 m 直线路线，估计轮速与仿真地面轮速有偏差 | 模拟车停在约 (0.68 m, 0.02 m)，坐标以模拟地面真值计算 |
| 1.6 m 目标，直线路径中放置宽 0.4 m 的障碍 | 小车绕行并停车，地面真值约 (1.61 m, −0.13 m)，仿真半径 10 cm 的车身接触计数为 0 |
| 12 × 10 m 场景的自主探索 | 自动选择探索目标，推进约 1.9 m 后因持续缺失回波而暂停；未覆盖整层 |
| 合成单墙、双墙；通信和测距故障 | 测试覆盖单墙法向修正、双向平移校正、失联、SW1、过期与缺失回波、转向后旧样本、AT 帧分包与断连 |

教学楼验收请分别记录已覆盖面积、每平方米用时、返回起点的漂移、最小墙距及漏检物。细椅腿、斜面、吸声物和探头高度以外的物体都是单超声波的盲区；在大于有效量程的开阔处，回波缺失会触发停车。完成整层地图、复访同一地点和无人巡视仍需现场数据、可靠里程反馈和补盲验证。建议先在有人看护的单间验证，再扩到一段走廊。
