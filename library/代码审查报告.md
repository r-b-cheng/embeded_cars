# clib 代码审查报告

**审查日期**：2026-11-12
**审查方式**：4 路子代理并行 + 主代理独立编译验证
**范围**：`organized/library/` 下全部 10 对 `.h/.c`、`ports/`、`tests/`、`Makefile`、3 份 README，以及与原案例源码的逐项比对
**结论**：共发现 2 个严重问题、1 处事实性编造、20 余项一般问题；**全部已修复并重新编译验证**。未采纳 1 条建议（附理由）。

---

## 一、四路分工

| 路 | 职责 | 主要产出 |
|---|---|---|
| 1 | 编译 / 静态分析 / 内存与 UB | 四级优化零告警；抓出 float→uint32 UB、输出缓冲无容量参数、串口错误码被吞 |
| 2 | API 一致性 / 头文件自包含 / 文档核对 | 10/10 头自包含通过；抓出 Makefile 库外执行失败、C++ 包装缺失、注释与参数不一致 |
| 3 | 与原案例语义一致性 | 8 模块核心数值全部抄对；抓出 legacy 公式漏 `*10`、**主代理编造的「1 计数=5us」**、案例归属错误 |
| 4 | 可移植性 / 实时性 / 资源 / 中断安全 | 零芯片依赖通过；抓出 **两个 poll 活锁**、TM4C 骨架漏 PWM 时钟分频、16 位捕获溢出 |

## 二、严重问题（已全部修复）

| # | 问题 | 位置 | 修复 |
|---|---|---|---|
| S1 | `clib_frame_poll` 的 `for(;;)` 在持续噪声下永不返回，找帧头阶段超时保护还因 `len==0` 失效 → 饿死 1kHz 控制环 | `clib_frame.c` | 加 `CLIB_FRAME_POLL_BUDGET=16` 字节预算；超时判断纳入 `state/head_pos` |
| S2 | `clib_k210_poll` 同结构活锁，且 state0 收到非 `AA` 时既不 reset 也不报错 | `clib_vision_k210.c` | 加 `CLIB_K210_POLL_BUDGET=16` 字节预算 |
| S3 | `clib_echo_count_to_cm()` 里 `(uint32_t)(float 乘积)` 在溢出时是 **C99 未定义行为**（原注释"防溢出"恰好反了） | `clib_ultrasonic.c` | 改 `uint64_t` 乘法 + 显式饱和到 `UINT32_MAX` |
| S4 | `clib_frame_feed()` 无 `payload_cap` 参数却按 `body_len` 写调用方缓冲，可溢出栈 | `clib_frame.c/.h` | `feed/feed_buf/poll` 全部加 `payload_cap`，写前检查，容量不足返回 `CLIB_ERR_OVERFLOW` |
| S5 | **事实性编造**：主代理在超声波注释/README 里臆断「1 计数 = 5us」「原公式比物理值大 10 倍」。原 `timer.c` 实为 `TIM_Period=5000, TIM_Prescaler=7199` → 72MHz/7200 = 10kHz，即 **100us/计数** | `clib_ultrasonic.c/.h`、`README.md`、`stm32f103/README.md` | 删掉臆断，按 `timer.c` 事实重写；明确 `us_per_count=100`；补 `CLIB_ULTRA_LEGACY_US_PER_CNT` |
| S6 | `clib_echo_count_to_legacy()` 只复现 `cnt*0.85`，但文档声称「兼容旧阈值 60」——阈值 60 判的是 `StartMeasure()` 返回的 `cnt*8.5`，差 10 倍 | `clib_ultrasonic.c/.h` | 新增 `clib_echo_legacy_measure()` 复现 `cnt*8.5`，文档明确两者区别与「单位不是 cm」 |
| S7 | TM4C 骨架漏 `SysCtlPWMClockSet(SYSCTL_PWMDIV_1)`，按 `SysCtlClockGet()` 算 period 会得到电机 10kHz / 舵机 25Hz | `tm4c123g/README.md` | 骨架与初始化步骤补上，并列入踩坑表 |
| S8 | TM4C 骨架用 16 位拆分对 `TIMER_CFG_SPLIT_PAIR|CAP_TIME` 测 HC-SR04 回波，80MHz 下 819us 溢出，30ms 回波必错 | `tm4c123g/README.md` | 改为 32 位计数或加预分频+溢出补偿，两种方案都写明 |

## 四、未采纳的建议（附理由）

| 建议 | 不采纳的理由 |
|---|---|
| 审查 1 建议「`clib_frame_reset()` 内加 `f->cfg = NULL`」 | **会破坏正常流程**：每收满一帧都会调 `reset()`，清掉 cfg 后下一次 `feed()` 就因 `cfg==NULL` 返回 `CLIB_ERR_NOT_INIT`，解析器直接失效。正确约束是「必须先 `clib_frame_init()`」，已在源码注释与头文件写明。`clib_frame_init()` 本身用 `memset` 全清，初始化路径是安全的。 |
